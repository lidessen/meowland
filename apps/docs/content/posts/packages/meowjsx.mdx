# MeowJSX

MeowJSX is the rendering runtime the rest of the library sits on. It renders a tree of nodes, and it
lets a component bind a signal to an attribute or a text node, so a later change reaches the DOM
without re-rendering the tree.

## Setup runs once

A component uses an ordinary function declaration, types its context as `Context<typeof Toggle>`, and attaches the finite part list as `.meta`. Binding the root descriptor with native `ref` keeps the host element in normal JSX.

```tsx
import { mapSignal, type Context, type MaybeSignal, type Props } from "meowjsx";

export interface ToggleProps extends Props {
  /** Controlled when provided; a signal keeps it live. */
  pressed?: MaybeSignal<boolean>;
  onPressedChange?: (pressed: boolean) => void;
}

export function Toggle(
  { pressed = false, onPressedChange, children, ref, ...props }: ToggleProps,
  context: Context<typeof Toggle>,
) {
  return (
    <button
      {...props}
      type="button"
      aria-pressed={mapSignal(pressed, (value) => String(value))}
      onClick={() => onPressedChange?.(!pressed)}
      ref={[context.parts.root, ref]}
    >
      {children}
    </button>
  );
}
Toggle.meta = { name: "toggle", parts: ["root"] } as const;
```

The setup body still runs once for that mount; `.meta` supplies stable component identity and the finite parts available through `context.parts`.

## The pieces

- `createRuntime` builds an isolated runtime with its own component registry, plugins and shadow
  registry. A runtime is a real boundary: two runtimes never share a context, a registry entry or a
  symbol.
- `createWebRenderer(runtime).renderToHtml(node)` produces static HTML from a tree, and
  `createWebRenderer(runtime).render(node, host)` mounts a live tree into the DOM.
- `h`, `Fragment` and the `Props` and `Child` types are the JSX surface. The root entry does not
  depend on the DOM; the web entry does.

<Callout tone="note">
  The runtime entry never touches the DOM. Anything that needs a document imports from
  `meowjsx/web`.
</Callout>
