# Meowtail

Meowtail provides cross-application components, semantic layout, the standard theme and the complete
Assistant composition. Networking, execution, permissions and persistence stay with the host.

## Three steps to a working page

Register the components on the runtime that renders the page, deliver the stylesheet, then bind the
theme root. This browser entry assumes the page contains `<main id="app"></main>`.

```tsx
import { createRuntime, h } from "meowjsx";
import { createWebRenderer } from "meowjsx/web";
import { applyTheme, mountStyles } from "meowcss/web";
import { Button, createMeowUI } from "meowtail";
import { standardTheme } from "meowtail/theme";

const host = document.querySelector<HTMLElement>("#app");
if (!host) throw new Error("Missing app root");

const runtime = createRuntime();
const uninstall = runtime.use(createMeowUI({ components: [Button] }));
const removeStyles = mountStyles(host.ownerDocument, standardTheme.cssText);
const removeTheme = applyTheme(host, standardTheme);
const mounted = createWebRenderer(runtime).render(<Button>Save</Button>, host);

export function dispose() {
  mounted.unmount();
  removeTheme();
  removeStyles();
  uninstall();
}
```

Call `dispose` when the host is destroyed. Component imports, registration and theme delivery each
have a separate job. Register every family rendered by the host and its compositions. A host that
needs the full catalog can import `meowUIComponents` from `meowtail` and pass it as `components`.
The selective factory does not import the full catalog itself.

The standard theme provides typography, component rules and utility classes. It does not reset
`html` or `body` margins or allocate the page layout. Compose a page with `Page`, `Stack`, `Inline`
and `Grid`; register those components when the page uses them.

## Class lists and cx

Use `ui` from `meowtail/theme` for the built-in class catalog and `cx` from `meowcss` for a reusable
composition. Both forms below use rules already delivered by the standard theme.

```tsx
import { h } from "meowjsx";
import { mapSignal, signal } from "meowjsx/signal";
import { cx } from "meowcss";
import { ui } from "meowtail/theme";

const panelClasses = cx(ui.p.panel, ui.bg.raised, ui.radius.xl);
const selected = signal(false);

export const panel = (
  <section className={[panelClasses, mapSignal(selected, (on) => on && "is-selected")]}>
    <p className={[ui.text.caption, ui.color.secondary]}>Changes saved</p>
  </section>
);
```

`className` keeps nested lists and Signals live. `cx` composes class values and strings; it preserves
declarations for reuse in a CSS template. Use a class list when forwarding a caller's `className`,
since that prop may contain Signals. JavaScript supplies conditions, and theme CSS supplies hover,
focus and responsive rules. Stylesheet order and the CSS cascade resolve conflicts. The
[MeowCSS guide](/packages/meowcss/#class-values-and-cx) covers declaration expansion and custom catalogs.

<h2 id="a-component-declares-the-theme-paints">A component declares, the theme paints</h2>

A component names its parts and finite style options in static `meta`. Keep shared options in a
module that imports no component implementation.

```ts
// callout.options.ts
import { defineOptions } from "meowcss";

export const calloutOptions = defineOptions("callout", {
  tone: ["neutral", "accent"],
});
```

The component forwards native props, including the caller's class list, and explicitly composes the
caller ref with its root part. Its function body runs once per mount.

```tsx
// callout.tsx
import { h, type Context, type Props } from "meowjsx";
import { defineStyleProps, type ThemedProps } from "meowcss/meowjsx";
import { calloutOptions } from "./callout.options";

export interface CalloutProps extends Props, ThemedProps<typeof calloutOptions> {
  title: string;
}

export function Callout(
  { title, children, ref, ...props }: CalloutProps,
  context: Context<typeof Callout>,
) {
  return (
    <aside {...props} ref={[context.parts.root, ref]}>
      <strong ref={context.parts.title}>{title}</strong>
      {children}
    </aside>
  );
}
Callout.meta = {
  name: "callout",
  parts: ["root", "title"],
  style: defineStyleProps(calloutOptions, { defaults: { tone: "neutral" } }),
} as const;
```

The theme type-imports the component to address its finite parts. It runtime-imports the shared
options, then paints the parts with tokens and class-value declarations.

```ts
// callout.theme.ts
import type { Callout } from "./callout";
import { css, parts } from "meowcss/meowjsx";
import { extendStandardTheme, ui, uiTokens } from "meowtail/theme";
import { calloutOptions } from "./callout.options";

const callout = parts<typeof Callout>("callout");
export const calloutTheme = extendStandardTheme({
  styles: [
    css`
      ${callout.root} {
        display: grid;
        gap: ${uiTokens.space.group};
        ${ui.text.body}
        ${ui.bg.fill}
        ${ui.p.group}
        border-radius: ${uiTokens.radius.lg};
        border: ${uiTokens.line.width} solid ${uiTokens.line.edge};
        ${calloutOptions.when({ tone: "accent" })} {
          border-color: ${uiTokens.accent.line};
          background: ${uiTokens.accent.soft};
        }
      }
      ${callout.title} {
        font-weight: ${uiTokens.type.weight.semibold};
      }
    `,
  ],
});
```

Core binds the part identity through `ref`. The style-props adapter registered by `createMeowUI`
consumes `tone` and writes its generated option attribute on the root carrier. Components do not
hand-write those attributes. `parts<typeof Callout>("callout")` exposes only the parts declared in
`Callout.meta`, and `defineStyleProps` checks the allowed defaults.

To mount this custom component, use the same lifecycle as the first example with
`components: [Callout]`, `calloutTheme` and `<Callout title="Saved" tone="accent">Your changes are
ready.</Callout>`. Extended themes reuse the standard token and fragment objects, including one
utility fragment after the component styles. Keep those shared identities when assembling a theme.

## Import only what you use

The package declares `sideEffects: false` and every public entry is plain ESM, so a bundler keeps
only what you import. `uiTokens` or `ui` alone does not bring in components, the JSX runtime or the
theme rules; `standardTheme` brings the complete stylesheet; a `Button` import does not bring other
components. Shiki loads only with the code surfaces (`CodeBlock`, `ReadBlock`, `JsonBlock`,
`AssistantView`). Register components with `createMeowUI({ components: [...] })`; `meowUIComponents`
is the full catalog and keeps every component.

## This site is made of it

The site uses Meowtail for shared frames, tables, badges and links, with site layout in its own
theme. Stories supply scenario data and drive real components; the documentation app does not copy
their implementations. Each component reference lists its `meta` name, style axes and finite parts.
