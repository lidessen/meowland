# Presentation entrance transitions

This round adds browser entrance decoration to the existing Presentation / Reveal, reusing the same position source, single-current-slide mounting, and activity permission; it does not introduce a timeline, animation framework, or PPT export. An independent challenger reviewed counterexamples for fast navigation, initial mount, nested Reveal, animation cancellation, and media cleanup, then approved this bounded approach.

`transition` uses the same contract in both components: `none | fade | slide | zoom`, or `{ effect, direction?, speed? }`. The default none keeps older works unchanged. speed is fast / normal / slow (160 / 280 / 420ms); direction is the physical movement direction: left enters from right to left, up enters from bottom to top. When unspecified, advancing through slides in array order uses left and going back uses right; Reveal defaults to up. fade / zoom do not use direction.

A slide change only animates the new slide's entrance; the old slide stops and unmounts immediately. There is no push that requires the old slide to move out or keep a snapshot. Slide order and step are narrative state: animation does not delay navigation and does not keep old interactions or media alive. Slide content remains fully interactive during entrance. A Reveal threshold decides visibility, inert, and activity; animation only decorates an already-mounted element going from hidden to shown and does not change geometry or delay hiding. Initial direct navigation, ancestor permission recovery, or a parent Reveal becoming visible does not replay inner animations.

It uses native Web Animations and decorates only opacity / translate / scale, preserving the canvas's existing fit transform. During a slide change, the entrance frame is temporarily clipped on the existing stage and restored uniformly on completion or cancellation; the viewport's actual-size scroll contract is unchanged. Fast navigation cancels the old decoration first and starts only on the next frame corresponding to the latest navigation. Reduced motion, activity revocation, unmount, and subsequent navigation all terminate the decoration and present its end state; restoring permission does not replay it. SSR, missing animation capability, or a browser rejecting the animation presents the end state.

Regressions required by the independent review include fast forward/backward and cross-outline navigation, old media stopping with DOM removal, same-slide steps not remounting, nested thresholds, focus fallback, activity/document-hidden/reduced-motion revocation, and temporary clip restoration under zoom and actual-size. Final evidence is recorded in this round's receipt; animation correctness is not inferred from static images.
