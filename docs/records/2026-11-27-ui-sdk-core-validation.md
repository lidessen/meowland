# Validation of `@ui-sdk/core` (`0.1.0-beta.17`) for Meowtail behaviors

Status: decided (**Write our own**); opens Phase 1 of [the UI system maturity plan](../designs/2026-11-27-ui-system-maturity-plan.md).

## Decision

**Write our own** (`meowtail/behaviors`).

Every one of the seven adoption criteria had to hold to adopt `@ui-sdk/core`. The spike established that `@ui-sdk/core` fails the bundle budget (more than 7.6x over the 6 KB gzip limit), fails Playwright behavior parity on `Toolbar`, leaks runtime `window` assumptions during SSR under Happy DOM test suites, and hardcodes `ownerDocument.activeElement` in key focus paths instead of `getRootNode().activeElement`.

We also evaluated the intermediate outcome (**Adopt the test kit only**), which requires `@ui-sdk/core/testing`'s pattern, server, and direction checks to run cleanly against Meowtail. Only `checkPattern` operates on rendered DOM directly; both `checkServer` and `checkDirection` require `@ui-sdk/core`'s `definePrimitive` schema and throw when given MeowJSX components, and `checkPattern` itself assumes `doc.activeElement` rather than shadow-root active elements and `root instanceof Document` (requiring a `Document = HTMLDocument` shim under Happy DOM 21). Neither package adoption nor test-kit-only adoption fits.

Meowtail will write internal `meowtail/behaviors` keeping `@ui-sdk/core`'s behavior names and option shapes (`createListbox`, `createRovingFocus`, `createTypeahead`, `createSelection`, `createFocusRecovery`) plus lightweight MeowJSX-native test helpers covering APG patterns, SSR purity via `renderToHtml`, RTL direction symmetry, and open `ShadowRoot` resolution. Notably, the baseline `checkPattern` run surfaced a real APG gap in today's `ChoiceSelect` (`has no tab stop` in non-searchable `listbox` mode), which Phase 1 will fix alongside extracting shared listbox/roving behaviors.

## Setup

A throwaway spike branch (`spike/ui-sdk-core`, now discarded) pinned `@ui-sdk/core@0.1.0-beta.17` in `packages/meowtail/package.json` and rebuilt the two plan target components without changing their public APIs, `[data-meowui-part]` markup, or theme rules:

- **Adapter** (`packages/meowtail/src/behaviors/ui-sdk-adapter.ts`): `createSignalStore` backed directly by MeowJSX `WritableSignal` instances (no mirror `createStore`) and `createSignalPrimitiveContext` bridging `options`, `parts`, `element`, and `onDestroy`.
- **Toolbar** (`packages/meowtail/src/components/toolbar.tsx`): rebuilt on `createRovingFocus`.
- **ChoiceSelect** (`packages/meowtail/src/components/choice-select.tsx`): rebuilt on `createListbox`, `createTypeahead`, and `createPopup` (`popoverPreset` from `@ui-sdk/core/popover`).

## Bundle size measurements

All measurements ran `Bun.build` with `--minify` and externals `["meowjsx", "meowjsx/signal", "@floating-ui/dom", "lucide"]`:

| Target                                                                                                  | Baseline gzip | Rebuilt gzip |                                                        Delta |
| ------------------------------------------------------------------------------------------------------- | ------------: | -----------: | -----------------------------------------------------------: |
| `toolbar.tsx` (`createRovingFocus`)                                                                     |       1,321 B |      4,012 B |                                          +2,691 B (+2.63 KB) |
| `choice-select.tsx` (default minify)                                                                    |       5,395 B |     48,263 B |                                        +42,868 B (+41.86 KB) |
| `choice-select.tsx` (`NODE_ENV="production"`)                                                           |             — |     46,720 B |                            +41,325 B (+40.36 KB) vs baseline |
| Combined split (`choice-select` + `toolbar`)                                                            |       6,890 B |     53,679 B |                                    **+46,789 B (+45.69 KB)** |
| Pure helper subset (`createListbox` + `createTypeahead` + `createRovingFocus`, `NODE_ENV="production"`) |             — |      7,758 B | **+7.58 KB** (already > 6 KB before component glue or popup) |

The `Bun.build` metafile for rebuilt `ChoiceSelect` pulled **77 modules (371,243 source bytes)**, driven by `createPopup` + `popoverPreset`: `popup.js` (35,242 B), `position.js` (22,065 B, duplicating `@floating-ui/dom`), swipeable mobile sheet code (`sheet-pointer.js`, `sheet.js`, `sheet-scroll-snap.js`, `sheet-effects.js`, `drag-and-drop/pointer.js` totaling ~59.7 KB source), `listbox-engine.js` (18,635 B), `dev.js` (14,418 B), `motion/machine.js` (10,497 B), `layers.js` (9,147 B), and `modal.js` (7,431 B).

## Next

With `@ui-sdk/core` rejected under the plan criteria, Phase 1 proceeds by implementing `meowtail/behaviors` (`createListbox`, `createTypeahead`, `createRovingFocus`, `createSelection`, `createFocusRecovery`) and Meowtail's own contract/APG/SSR/RTL/ShadowRoot check helpers, starting with fixing `ChoiceSelect`'s baseline listbox tab stop and unifying keyboard navigation across `ChoiceSelect`, `Autocomplete`, `CommandPalette`, `ChatComposer`, `Menu`, `Toolbar`, `Tabs`, `TreeView`, and `SegmentedControl`.
