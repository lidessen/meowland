# 内容与视觉迭代记录

当前作品标识为 `image-waiting-b2`；它是当前夹具的标识，不表示仓库中存在已提交的 b1 版本。以下只记录本次实际可核修改，不补造方案评审或用户选择历史。

## 已发生的粗稿与替换

开场、左右排版与最难实验页在同一份 `talk.tsx` 粗稿中建立。图片从首次完整源文件起就引用实际原创 PNG/JPEG；未保留可复查的早期图片占位版，因此不宣称已验收图片占位替换。12 秒视频文件先短暂使用本地静态画面作为明确开发占位，随后实际运行 `scripts/record-transfer.ts`，用浏览器真实本地 HTTP 请求录屏覆盖。占位视频未保留为可复查发布物，最终文件由 `records/recording.json` 记录的真实过程生成。

## 已发生的局部改稿

以下修改均保留既有左右布局、页 id、共享参数和其余文稿：

- 独立审查指出“缓存也只会增加时间”错误；只修改实验末步，改为未缓存、固定吞吐的纯传输估算，明确热缓存可避免传输。
- 独立审查指出“Same pixels”可误导为像素值无损；只改比较页标题为“Same dimensions. Fewer bytes.”，与实际 2200×1400 尺寸及 JPEG 有损事实一致。
- 实际深色系统偏好截图发现暗舞台与固定深绿文字对比失败；作品宿主通过公共主题选择固定浅色，同时用公开 presentation tokens 接选定米白/深绿/陶土色。不复制通用舞台或播放器结构。
- 移除作品对所有按钮 `font: inherit` 的多余覆盖，恢复共享按钮尺度；视频高度限制改在真实 video 上，避免包装容器截断媒体控制。

## 可复验的局部修改方式

若下一轮反馈是“保留当前左右 B 排版，仅改结论和图”，应只 patch 相关文稿与素材引用，真实执行图片替换、测字节、观察裁切并重录受影响证据，不能把该推荐路径写成已经完成。重排只移动现有 `slides` 条目，稳定 id 不跟页序变；步骤含义变化后重新确认定位。

复验配方：`experiment / step=3 / image-waiting-b2 / speed=71` → Open evidence → Return to experiment → summary。公式与总结都应继续使用71 Mbit/s。源码用普通 Git 检查点回退，素材版本见来源说明与录屏记录。
